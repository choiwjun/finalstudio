인공지능 윤리는 안내문에서 네 가지 빈칸을 찾는 일부터 시작합니다. 누구에게 불리할 수 있는지, 결과의 이유를 설명하는지, 데이터를 어떻게 처리하는지, 문제가 생기면 누가 대응하는지를 차례로 살펴봅니다.

AI 서비스 설명이나 뉴스, 공모 안내를 읽을 때는 `공정`, `안전`, `신뢰` 같은 표현보다 확인 가능한 근거와 책임 경로를 먼저 찾습니다.

## 핵심 요약

아래 표에서 답이 비어 있는 항목을 표시하면 안내문을 빠르게 점검할 수 있습니다.

| 확인할 쟁점 | 먼저 물을 질문 | 답이 없을 때 |
| --- | --- | --- |
| 알고리즘 편향 | 특정 사람이나 상황에 결과가 다르게 나타날 가능성이 있습니까? | 데이터와 평가 범위를 찾아봅니다. |
| 설명가능성 | 결과가 나온 이유와 한계를 설명합니까? | 결과만 믿지 말고 판단 근거를 요청합니다. |
| 데이터 프라이버시 | 어떤 데이터를 입력하고 저장·이용·공유합니까? | `[직접 확인 필요: 데이터 처리·보관·삭제·공유 조건]`을 남깁니다. |
| 책임 소재 | 오류가 생기면 누가 설명하고 수정합니까? | 문의·신고·수정 절차를 찾아봅니다. |

## AI 안내문 한 문장을 점검표로 바꾸는 방법

안내문의 홍보 문장은 주장·근거·빈칸으로 나누어 적으면 점검표가 됩니다. 다음 문장은 실제 서비스가 아닌 확인 연습용 예시입니다.

> 이 서비스는 지원서 내용을 분석해 공정하고 안전한 추천 결과를 제공합니다. 입력한 내용은 서비스 개선에 활용됩니다.

| 안내문 속 주장 | 추가로 물을 질문 | 문장에 빠진 근거 |
| --- | --- | --- |
| 공정한 추천 결과 | 어떤 데이터를 기준으로 평가했습니까? 특정 지원자나 상황에서 결과가 달라질 수 있습니까? | 평가 대상과 오류 범위 |
| 안전한 결과 | 추천 이유와 판단의 한계를 설명합니까? 이의를 제기할 수 있습니까? | 설명 방식과 이의 제기 절차 |
| 서비스 개선에 활용 | 입력 정보는 얼마나 보관합니까? 삭제·공유를 요청할 수 있습니까? | 보관 기간, 삭제, 공유 조건 |
| 추천 서비스 운영 | 오류 신고를 어디에 접수합니까? 수정 권한은 누구에게 있습니까? | 운영 주체와 책임 경로 |

이 예시의 기록은 다음처럼 남길 수 있습니다.

```text
핵심 주장: 공정하고 안전한 추천 결과를 제공함
확인된 근거: 입력 내용을 서비스 개선에 활용한다고 안내함
추가 확인 필요: 평가 데이터, 추천 이유, 보관 기간, 삭제·공유 조건
판단: 추가 확인 필요
다음 행동: 개인정보 처리 안내와 오류 문의 경로 확인
```

| 기록 항목 | 작성 내용 |

| 핵심 주장 | 안내문이 약속하는 결과를 한 문장으로 적습니다. |
| 편향 관련 근거 | 평가 대상, 제외된 상황, 결과 차이를 적습니다. |
| 설명 관련 근거 | 결과의 이유와 한계를 적습니다. |
| 데이터 관련 근거 | 수집·이용·보관·삭제·공유 조건을 적습니다. |

## 네 가지 기준에서 찾아야 할 근거

네 가지 기준은 윤리 용어를 외우기 위한 목록이 아니라 안내문에 빠진 조건을 찾기 위한 질문입니다. 출처 목록의 자료는 공모 안내와 편향·투명성·프라이버시·책임을 다룬 참고 자료로 나누어 볼 수 있으며, 이 글에서는 특정 사례를 확대하지 않고 공통 점검 기준으로 정리했습니다.

### 알고리즘 편향은 결과가 누구에게 다르게 나타날 수 있는지 보는 기준입니다

알고리즘 편향은 학습 데이터나 설계 조건 때문에 특정 사람이나 상황에 결과가 불리하게 나타나는 문제입니다.

결과가 정확해 보여도 모든 사람에게 공정하다고 단정할 수는 없습니다. 어떤 데이터를 기준으로 만들었는지, 평가에서 빠진 사용자나 상황은 없는지 살펴봅니다.

- 데이터의 범위와 평가 대상이 설명되어 있습니까?
- 특정 사용자나 상황에서 성능이 달라질 가능성을 언급합니까?
- 문제가 발견됐을 때 재검토하거나 수정하는 절차가 있습니까?

### 설명가능성은 결과의 근거와 한계를 사람이 이해할 수 있는지 보는 기준입니다

설명가능성은 AI가 결과를 낸 이유와 한계를 사람이 이해할 수 있도록 판단 근거를 보여주는 성질입니다.

결과만 제시하면 사용자는 오류를 발견하거나 이의를 제기하기 어렵습니다. `공정한 결과`, `안전한 판단`처럼 평가만 적혀 있다면 결과에 영향을 준 입력과 기준을 더 찾아봅니다.

- 결과에 영향을 준 주요 기준은 무엇입니까?
- 잘못된 결과가 나왔을 때 이의를 제기할 수 있습니까?
- 설명의 범위와 한계가 함께 적혀 있습니까?

### 데이터 프라이버시는 제공한 정보의 처리 범위를 확인하는 기준입니다

데이터 프라이버시는 AI에 입력한 정보가 수집·이용·보관·삭제·공유되는 범위를 살피는 문제입니다.

서비스를 사용하기 전에는 입력 정보의 이용 목적과 처리 조건을 확인해야 합니다. 조건을 찾지 못했다면 `[직접 확인 필요: 입력 데이터의 이용 목적과 보관 조건]`으로 남기고, 확인 전에는 민감한 정보 입력을 보류합니다.

- 어떤 정보를 입력하게 합니까?
- 입력한 정보의 이용 목적이 설명되어 있습니까?
- 저장·삭제·공유 조건을 확인할 수 있습니까?
- 데이터 처리와 관련해 문의할 담당 창구가 있습니까?

### 책임 소재는 문제가 생겼을 때 대응할 주체를 찾는 기준입니다

책임 소재는 AI의 오류를 누가 설명하고 신고를 받으며 수정할지 확인하는 기준입니다.

`AI가 판단했다`는 설명만 있고 운영 주체나 문의 경로가 없다면 문제가 생긴 뒤의 대응 과정을 알기 어렵습니다. 서비스를 만든 곳과 결과를 사용하는 곳이 다를 수 있으므로 각자의 역할을 구분해 기록합니다.

- 서비스를 제공하거나 운영하는 주체가 표시되어 있습니까?
- 오류 신고와 문의 방법이 있습니까?
- 결과를 검토하거나 수정할 사람이 정해져 있습니까?
- 문제가 발생했을 때 답변을 받는 절차가 안내되어 있습니까?

## AI 서비스·뉴스·공모 안내를 읽는 순서

자료를 읽을 때는 핵심 주장 하나를 정한 뒤, 네 가지 기준에 맞는 근거를 나누어 찾습니다.

1. 안내문에서 핵심 주장을 한 문장으로 적습니다. 예를 들어 `공정하고 안전한 AI 서비스입니다`는 확인해야 할 주장입니다.
2. 주장을 편향, 설명가능성, 프라이버시, 책임 소재에 관한 질문으로 나눕니다.
3. 데이터 범위, 결과 설명, 정보 처리 조건, 문의 경로가 실제로 적혀 있는지 표시합니다.
4. 뉴스는 제목·본문·원출처를 분리해 읽습니다. 검색 결과의 제목과 설명만으로 사실을 확정하지 않습니다.
5. 공모 안내는 주제·참가 대상·접수 기간·제출물 이용 조건을 살핍니다. `[직접 확인 필요: 주최 기관의 공식 공고 URL과 최신 접수 조건]`을 남깁니다.
6. 각 항목을 `확인됨`, `추가 확인 필요`, `판단 보류`로 나누어 기록합니다.

| 자료 유형 | 우선 확인할 내용 | 근거를 찾을 곳 |
| --- | --- | --- |
| AI 서비스 | 데이터 처리, 결과 설명, 오류 문의 경로 | 개인정보 처리 안내, 이용 약관, 공식 문의 창구 |
| AI 관련 뉴스 | 보도 내용과 원출처의 일치 여부 | 원문 발표, 연구 자료, 기관 공식 안내 |
| AI 공모 안내 | 주최 기관, 참가 조건, 기간, 제출물 이용 조건 | 주최 기관의 공식 공고 |

## 자주 생기는 판단 오류와 해결 방법

### 상대 검색 지표를 인기도나 품질로 읽는 경우

상대 검색 지표는 정해진 범위 안에서 비교하는 값입니다. 절대 검색량이나 순위가 아니므로 AI 서비스의 안전성이나 정보의 신뢰도를 판단하는 근거로 사용하지 않습니다.

### 검색 결과 설명을 원문 확인으로 착각하는 경우

검색 결과의 제목과 설명은 원문을 읽기 전 참고 자료입니다. 원문에 같은 표현이 있는지, 어떤 기관이나 자료를 출처로 삼았는지 따로 살핍니다.

### 윤리 용어를 검증 결과로 받아들이는 경우

`공정`, `안전`, `투명`, `신뢰`라는 단어 자체는 검증 결과가 아닙니다. 해당 표현을 뒷받침하는 데이터 범위, 평가 방법, 처리 조건, 책임 절차가 함께 제시됐는지 확인합니다.

## FAQ

### 인공지능 윤리는 기술을 잘 알아야만 확인할 수 있나요?

기술 지식이 많지 않아도 네 가지 질문으로 기본 점검을 할 수 있습니다. 결과가 누구에게 불리할 수 있는지, 판단 이유를 설명하는지, 데이터를 어떻게 다루는지, 문제가 생기면 누가 대응하는지를 살피면 됩니다.

### 설명가능성이 부족하면 바로 위험한 AI인가요?

설명이 부족하다는 사실만으로 위험성을 확정할 수는 없습니다. 다만 사용자가 결과의 근거와 한계를 검토하기 어려우므로 `추가 확인 필요` 상태로 두는 편이 안전합니다.

### AI 서비스에 개인정보를 입력해도 되나요?

서비스의 데이터 처리·보관·삭제·공유 조건을 먼저 확인해야 합니다. 조건을 찾지 못했다면 `[직접 확인 필요: 해당 서비스의 데이터 처리 조건]`으로 표시하고 입력을 보류합니다.

### NAVER 상대 지표 100은 무엇을 뜻하나요?

상대 지표 100은 해당 요청 범위 안에서 가장 높은 상대값입니다. 절대 검색량, 전체 인터넷에서의 인기도, 검색 순위를 의미하지 않습니다.
