# 실용 튜토리얼 구조

이 템플릿은 `how-to` 글에 적용합니다.

## 권장 순서

1. 독자의 문제와 첫 해결책을 첫 문단에서 제시합니다.
2. 완성된 예시나 수식을 먼저 보여줍니다.
3. 예시에 필요한 도구·버전·전제 조건을 짧게 밝힙니다.
4. 번호 목록으로 실제 절차를 설명합니다.
5. 가장 많이 발생하는 오류 3개 안팎을 원인과 해결책으로 묶습니다.
6. 대안이나 버전별 선택 기준을 표로 정리합니다.
7. 검색형 FAQ 3개 안팎과 한눈에 보는 요약으로 끝냅니다.

## 작성 제약

- 한 글에서 중심 예시는 하나만 사용합니다.
- 정의를 길게 설명하기 전에 결과 화면이나 완성 수식을 보여줍니다.
- 오류 목록을 백과사전처럼 늘리지 않습니다. 독자의 다음 행동이 분명한 오류만 남깁니다.
- 직접 확인하지 않은 메뉴·버전·지원 범위는 검증 마커로 남깁니다.
- AI가 작성한 초안이라는 사실은 frontmatter와 운영 메타데이터로 관리하고 본문에서 반복하지 않습니다.

## SEO·AEO·GEO (how-to 전용)

### 제목·메타

- 제목(H1, frontmatter title): 검색 키워드가 앞쪽에 오는 문제 해결형, 25자 내외.
  예: "엑셀 중복 행 한 번에 찾는 법 — 원본은 그대로 두고". 비교 주제는 비교형("A vs B, ~ 비교")도 가능 — 비교 표 필수.
- 메타 디스크립션: 70~80자, 핵심 키워드 1회 포함, "이 글을 열어야 하는 이유"가 드러나게.
- 슬러그: 영어 소문자 + 하이픈 (예: `excel-remove-duplicate-rows`).

### 본문 최적화

- 첫 문단: 핵심 키워드를 자연스럽게 1회 포함, 첫 100자 안에 질문의 직접 답.
- H2는 독자의 여정 순서 5~7개: 요약 → 본론(방법) → 안 될 때 → FAQ → 정리. 소제목만 읽어도 흐름이 보이게.
- H3는 하나의 H2 안에서 2~5개. "정리" H2는 "한눈에 보기" 표로 마무리 (상황 → 방법 → 주의).
- 1,000자당 시각 요소(표·번호 리스트·스크린샷 자리) 하나 이상.
- 파생 키워드는 소제목·본문에 자연 분포. 나열·반복 금지.
- 내부 링크 1~3개(같은 시리즈 우선), 외부 링크는 공식 문서만 1~2개.

### AEO (답변 엔진)

- 각 소제목 아래 첫 문장이 곧 답. 배경 설명을 먼저 하지 않는다.
- 질문형 소제목 패턴 활용: "~원본을 지우고 싶지 않다면?" + 바로 아래 2~3문장 정답.
- 핵심 개념마다 40~60자 자기완결 정의문 (스니펫 인용 대상).
- **FAQ 섹션 필수**: 실제 검색형 질문 3~5개를 H3 질문 + 2~3문장 답으로.
- 절차는 번호 리스트(단계 스니펫 추출 대상), 비교·옵션은 표.

### GEO (생성형 엔진 인용)

- 문단 자기완결 — 앞 문맥 없이 읽혀도 의미가 완결될 것.
- 구체성: "최신 버전에서는" X → "2026년 9월 기준 엑셀 365에서는" O.
- 검증 가능한 사실은 한 문장으로 정리하고 공식 문서 출처를 붙인다.
- 통계·수치는 "어디서, 언제 기준"을 함께 쓴다. 근거 없는 수치 금지.

### 스크린샷 자리

- `[스크린샷: 무엇을 찍을지] ![alt 텍스트 초안]` — alt는 스크린샷 내용+키워드를 담은 한 문장.

## 출력 체크

- 첫 문단만 읽어도 해결 방법을 알 수 있는가?
- 각 H2 아래 첫 문장이 답인가?
- 수식·절차·오류·대안이 같은 예제를 가리키는가?
- FAQ 질문이 실제 검색형 질문인가?
- 마지막에 독자가 선택하거나 실행할 다음 행동이 있는가?
