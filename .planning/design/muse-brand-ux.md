## 1. 제품 약속 해석

CEO_PLAN 1.1의 약속을 UX 언어로 바꾸면 세 가지다.

1. **재현 가능성:** 다른 사람이 같은 화면에서 같은 결과를 낼 수 있다.
2. **실패 포함:** 성공 경로만이 아니라 막히는 지점과 해결책을 기록한다.
3. **한국 맥락:** 한국어 UI, 국내 업무 흐름, 버전·날짜를 명시한다.

이 약속이 지켜지는지는 본문 첫 화면에서 10초 안에 판단된다. 따라서 브랜드와 UX의 핵심 과제는 “검증됐다는 신호를 빨리, 구체적으로” 보여주는 것이다.

## 2. 독자 제안

CEO_PLAN은 1차 독자를 직장인·학생·1인 사업자로 정의했다. 그대로 두되, 탐색 행동 기준으로 네 유형으로 좁힐 것을 제안한다.

- **A. 스프레드시트 해결사:** Excel / Google Sheets에서 오류·수식·정리를 검색으로 찾아온다. 체류는 짧고 복사 가능한 답을 원한다.
- **B. Notion 운영자:** 템플릿·데이터베이스·권한 설정을 따라 하며 구축한다. 이미지보다 단계 순서에 민감하다.
- **C. Workspace 협업자:** Gmail·캘린더·문서 공유 설정과 실수를 줄이는 법을 찾는다. 모바일 확인 비중이 높다.
- **D. 검증된 AI 입문자:** 회의록·장문 요약·표 변환을 “직접 해본” 사례 중심으로 소비한다. 과장된 자동화 주장에 피로도가 높다.

설계 함의:

- 홈은 네 유형이 각자入口를 찾도록 주제별 갈래를 먼저 보여준다.
- 본문은 A/D의 “복사→실행→오류 해결” 흐름을 기본값으로 한다.
- B/C는 단계 번호, 전후 상태 비교, 설정 경로 표기에 민감하게 반응한다.

> ASSUMPTION: 유형별 비중, 유입 키워드, 모바일 대 데스크톱 비율은 미확인이다. Search Console 연결 전까지 A > D > B > C 순으로 가정하고 설계한다.

## 3. 브랜드 성격 제안

이름 `업무도구 실험실`은 유지가 타당하다. “실험실”이 약속과 직결되기 때문이다.

제안하는 성격 4축:

- **검증자, not 해설자:** “알려준다”가 아니라 “직접 해보고 기록한다.”
- **실패를 숨기지 않음:** 안 된 조건을 먼저 말한다.
- **과장 금지:** “AI 마법” 대신 입력·모델·수정한 과정을 공개한다.
- **한국 실무어:** 메뉴명은 한국어 UI 그대로, 괄호 영문은 최소로.

톤 가이드:

- 쓰기: “이 순서대로 하면 된다 / 이 조건에서는 안 된다 / 날짜·버전은 여기 있다.”
- 쓰지 않기: “초간단”, “무조건”, “누구나 1분”, 근거 없는 최고·최신 표현.
- 제목 규칙: `[도구] + [과제] + [조건/결과]` 형태를 권장한다. 예: “Google Sheets에서 중복 행을 찾고 원본을 보존하는 순서”.

> ASSUMPTION: 최종 작성자 정체성, 경력 공개 범위, 얼굴·실명 여부는 미확정이다. 아래 신뢰 설계는 “1인 전문가 + 사람 검토”를 가정한다.

## 4. 시각적 방향 제안

현재 `BaseLayout`은 좋은 출발점이다. 흰색 바탕, `#172033` 본문, `#174ea6` 링크, 960px 컨테이너, 46rem 본문 폭은 가독성 블로그에 적합하다.

유지할 것:

- 높은 대비의 본문, 넓은 줄간격 1.7, 카드형 목록.
- 한국어 중심 `system-ui` 폴백. 로딩 비용이 없고 정적 배포와 잘 맞는다.
- 과도한 장식 없음. 광고가 들어가도 본문과 구분하기 쉬운 구조다.

보강할 것:

- **검증 뱃지 영역:** 본문 상단에 테스트 날짜·도구 버전·AI 보조 여부를 한 줄 메타로 고정한다. 현재는 하단에만 `테스트 날짜`가 있다.
- **절차 가독성:** `h2` 단계, 번호 목록, 설정 경로(`메뉴 > 하위 메뉴`), 코드·수식, 표, 주의·경고 박스 스타일을 본문 CSS에 추가한다. 스프레드시트 글은 표와 코드 없이는 재현이 어렵다.
- **그림 규칙:** 캡처는 직접 제작, 개인정보 마스킹, 대체 문구는 “무엇을 보여주는지+상태”로 쓴다. 예: “중복 제거 전후 비교 화면”.
- **한글 타이포:** ASSUMPTION으로 Pretendard 자가호스팅은 P2로 미룬다. 현재는 시스템 폰트 유지가 성능과 유지보수에 유리하다. 단, 숫자·수식의 줄바꿈과 표의 모바일横스크롤은 P0에서 처리한다.
- **광고 대비:** 본문과 광고 경계를 색·레이블로 구분할 수 있도록 카드·본문 배경 토큰을 미리 분리한다. AdSense 연결 전 시각 규칙만 확정한다.

> ASSUMPTION: 다크모드 수요, 로고·심볼 필요성, 웹폰트 선호도는 미확인이다. 초기에는 라이트 단일 테마와 텍스트 브랜드를 가정한다.

## 5. 정보구조 제안

현재 IA:

```text
/ (최근 글)
/posts/[slug]
/about, /author, /contact, /privacy, /editorial-policy
```

제안 IA:

```text
/ (약속 + 주제 갈래 + 최근 검증 글 + 신뢰 요약)
/productivity (업무 생산성 목록)
/ai-workflows (AI 업무 활용 목록)
/posts/[slug] (본문)
/about, /author, /contact, /privacy, /editorial-policy
```

결정 제안:

- **D-IA-1:** 최상위 주제는 `productivity`와 `ai-workflows` 2개로 유지한다. CEO_PLAN의 70/30 비율과 스키마를 흔들지 않기 위해서다.
- **D-IA-2:** 하위 구분은 새 라우트 대신 본문 메타와 목록 필터로 표현한다. 예: Excel, Sheets, Notion, Workspace, 회의록, 문서변환. 스키마 변경이 필요하면 `tags[]`는 P1에서 검토한다.
- **D-IA-3:** URL은 `/posts/[slug]`를 유지한다. `slug`는 파일 경로에서 생성한다는 CEO_PLAN 규칙과 일치한다.
- **D-IA-4:** 홈 내비게이션에 주제 목록 진입점을 추가한다. 현재 헤더는 `/`, `/about`, `/editorial-policy`만 있어 주제별 탐색이 안 된다.
- **D-IA-5:** 검색은 P2다. 글이 20개 미만인 구간에서는 주제 목록+브라우저 찾기로 충분하다. ASSUMPTION: 초기 트래픽은 검색 유입 단일 글 랜딩이 중심이다.

## 6. 핵심 사용자 흐름

### 홈

목표: “여기는 검증된 실무 정보다”를 10초 안에 전달하고 주제 갈래로 보낸다.

제안 순서:

1. 약속 한 문장 + 대상 도구 범위.
2. 주제 갈래 2개 카드: 업무 생산성 / AI 업무 활용.
3. 최근 검증 글: 제목, 한 줄 해결 과제, 테스트 날짜, 도구 버전.
4. 신뢰 요약: 사람 검토, 직접 테스트, AI 사용 공개, 편집 원칙 링크.

현재 홈과의 차이: 약속 문구는 있으나 테스트 날짜·버전·주제 갈래가 목록에 없다. 빈 상태 문구(“첫 번째 검증 글을 준비하고 있습니다”)는 적절하므로 유지한다.

### 목록 (주제별)

목표: 같은 문제를 가진 글이 중복 없이 모여 있고, 어떤 글이 최신 검증인지 보인다.

제안 요소:

- 주제 설명 2문장: 무엇을 다루고 무엇을 다루지 않는지.
- 정렬은 검증일(`testedAt`) 우선, 발행일(`pubDate`) 보조. 현재 `lib/posts.ts`는 `pubDate` 정렬만 한다.
- 각 행에 테스트 날짜와 핵심 도구 버전을 노출한다.

> ASSUMPTION: 목록 페이지 URL과 페이지네이션 필요 시점은 미확정이다. 20개 이전에는 단일 목록+앵커로 가정한다.

### 본문

목표: 따라 하다가 막혔을 때 같은 페이지에서 해결한다.

제안 본문 블록 순서:

1. 상단 검증 메타: 테스트 날짜, 도구 버전, 작성자, AI 보조 여부, 소요 시간(선택).
2. 해결 요약: “이 글에서 해결되는 문제 1개 + 전제 조건”.
3. 따라 하기 단계: 번호 순서, 설정 경로, 수식·코드, 전후 화면.
4. 안 될 때: 오류 메시지, 원인, 해결책. 해당 없으면 이유를 한 줄로.
5. 출처·확인일: 주장별 `sourceIds`와 확인 날짜. 현재 스키마에는 있으나 화면에 노출되지 않는다.
6. 제한·다음 문제: 안 되는 조건과 관련 글 2~3개.

현재 본문과의 차이: 제목·날짜·작성자·설명·본문·하단 테스트 날짜만 있다. 목차, 단계 스타일, 오류 섹션 강제, 출처 노출, 관련 글이 없다.

## 7. 신뢰 형성 요소

AdSense·검색 품질 게이트(CEO_PLAN 4장)와 직접 연결되는 요소만 우선한다.

- **테스트 메타 노출:** `testedAt`, `toolVersions`를 본문 상단으로 이동한다. 하단 한 줄은 유지해도 되지만 상단이 본질이다.
- **출처 노출:** `sourceIds[]`를 빌드 검사에서 숨길 대상이 아니라 독자용 근거로 렌더링한다. 현재 `check-build.mjs`는 `sourceIds` 문자열을 금지어로 검사한다. 독자 화면에 “출처 3개·확인일” 형태로 보여주되 원시 필드명이 새지 않도록 렌더링 방식을 먼저 정해야 한다.
- **AI 사용 공개:** `aiAssisted`를 “AI 보조로 작성, 사람이 검증” 같은 한 줄 고지로 보여준다. About과 Editorial Policy의 문구와 일치시킨다.
- **작성자 실체:** Author 페이지는 현재 플레이스홀더다. 공개 전에는 경력·검증 방식·연락 경로·얼굴 공개 범위를 Human이 확정한다. 확정 전까지 공개 글을 만들지 않는다는 week0 규칙을 UX에서도 지킨다.
- **편집 원칙 연결:** 본문 하단과 푸터에서 Editorial Policy로 연결한다. 현재 푸터 연결은 이미 있다.
- **구조화 데이터:** Article, Breadcrumb, Organization/Person, 날짜(`datePublished`/`dateModified`)를 P1에서 추가한다. 현재는 canonical·OG 기본만 있다.
- **광고 구분:** 광고 삽입 위치를 본문 중간 자동 삽입보다 목록 하단·본문 하단 같은 예측 가능한 자리로 제한하는 것을 권장한다. 클릭 유도 문구는 반목표로 둔다.

> ASSUMPTION: 구조화 데이터·RSS·sitemap의 최종 요구사항과 Search Console 연결 시점은 도메인 승인 뒤로 가정한다.

## 8. 반목표

다음은 90일간 하지 않는다.

- 일반 AI 뉴스, 정의 설명, 이슈 추적.
- 금융·의료·법률·세금 지시와 가격·쿠폰 중심 글.
- 검증 없이 “직접 테스트했다”고 쓰는 표현.
- 댓글·회원·멤버십·실시간 대시보드. Supabase+Vercel 전환 조건이 성립하기 전에는 정적 단일 사이트를 유지한다.
- 무인 자동 발행과 분 단위 예약. 하루 한 번 빌드와 사람 승인 게이트를 유지한다.
- 본문과 구분되지 않는 광고, 클릭 유도, 자체 클릭, 트래픽 조작.
- 타사 화면·로고·템플릿의 권리 미확인 재배포. 불확실하면 텍스트 설명과 직접 예제로 대체한다.
- `.planning/`과 내부 검토 자료의 공개. CI 검사는 유지한다.
- 글 수 늘리기 위한 중복·바꿔쓰기. 승인 기준을 낮추지 않는다.

| 신뢰 페이지 | 5종 라우트 존재, About·Editorial Policy에 원칙 있음 | Author·Contact·Privacy는 플레이스홀더. 공개 전 Human 확정 필요 |
| SEO·메타 | canonical·description·OG 기본, 조건부 sitemap·robots 있음 | RSS, JSON-LD, OG 이미지, 주제별 canonical 전략 없음 |
| 검사 | `check-content`, `check-build`로 비공개·TBD 유출 방지 | `sourceIds`를 무조건 금지어로 보면 독자용 출처 노출과 충돌. 렌더링 방식 결정 필요 |
| 시각 스타일 | 최소 청회색 시스템, 카드·본문 폭 적절 | 절차·표·코드·주의 박스·모바일 표 처리·광고 구분 토큰 없음 |

## 10. 실행 가능한 설계 결정

- **D-BRAND-1:** 사이트명 `업무도구 실험실` 유지. 부제는 “직접 테스트한 업무 생산성 가이드”로 고정한다.
- **D-BRAND-2:** 글 제목은 `[도구] + [과제] + [조건]`을 기본으로 한다. 예: 조건·버전이 제목에 과도하게 길면 설명문으로 옮긴다.
- **D-UX-1:** 본문 상단에 검증 메타를 고정한다. 포함 항목: 테스트 날짜, 도구 버전, 작성자, AI 보조 여부.
- **D-UX-2:** 본문 템플릿을 `요약 → 전제 → 단계 → 오류 해결 → 출처·확인일 → 제한·다음` 순서로 고정한다.
- **D-UX-3:** 목록 카드에 테스트 날짜를 필수 노출한다. 도구 버전은 공간이 허락하면 노출한다.
- **D-UX-4:** 홈에 주제 갈래 2개와 신뢰 요약을 추가한다. 기존 빈 상태 문구는 유지한다.
- **D-UX-5:** 출처는 ID 원문 노출이 아니라 “출처명·확인일” 카드로 렌더링한다. `check-build` 금지어 규칙과 충돌하지 않도록 구현 전에 렌더링 형식을 확정한다.
- **D-VIS-1:** 절차·표·코드·인용·주의 박스의 최소 스타일을 먼저 추가한다. 웹폰트·다크모드·로고는 하지 않는다.
- **D-TRUST-1:** Author·Contact·Privacy는 공개 전까지 플레이스홀더를 유지하고, 공개 글 발행과 AdSense 연결을 차단한다. week0 규칙과 일치한다.
- **D-SEO-1:** P0에서는 제목·설명·canonical·alt 일치에 집중한다. JSON-LD·RSS·OG 이미지는 P1이다.
- **D-SCOPE-1:** 검색·댓글·회원·다국어는 90일 범위 밖으로 둔다.
