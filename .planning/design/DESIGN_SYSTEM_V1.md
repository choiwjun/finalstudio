# DESIGN_SYSTEM_V1 — WJ Blog 일반 블로그 디자인 시스템

- 상태: **v1 전면 재설계 구현 완료(로컬), 브라우저 최종 QA 대기**
- 목적: v0의 랜딩페이지형 구조와 과한 매거진 연출을 폐기하고, 일반적인 블로그 기본 구조로 전환한다.
- 근거: `../research/blog-design-benchmark-2026-09-06.md`
- v0 기록: `DESIGN_SYSTEM.md`는 반려된 시안의 역사 기록으로만 보관한다.

## 1. 디자인 방향

`WJ Blog`는 특별한 서비스 화면이 아니라, 주제만 계속 교체·확장할 수 있는 일반적인 한국어 개인 블로그다.

- **시각 인상**: 밝은 배경, 단순한 헤더, 읽기 쉬운 제목·요약·날짜, 필요한 만큼의 카드와 구분선.
- **배제**: 큰 브랜드 연출, 강의 플랫폼처럼 보이는 통계·챌린지·회원 활동, 장식용 패널.
- **핵심 행동**: 홈 방문 → 주제 선택 → 글 목록 훑기 → 본문 읽기.

## 2. 정보 구조

### 전역

- 브랜드: 홈으로 이동
- `카테고리`: `/categories`
- `카테고리별 글`: `/categories/<category>`
- `소개`: `/about`
- `검색`: `/search`
- 편집 원칙·작성자·문의·개인정보처리방침: 푸터 보조 링크

모바일에서 메뉴를 숨기거나 햄버거 안에 넣지 않고 자연스러운 2행 래핑으로 노출한다. 모든 핵심 경로는 첫 화면에서 발견 가능해야 한다.

### 홈 `/`

1. 짧은 블로그 소개
2. 최근 글 목록
3. 주제 사이드바
4. 글 검색과 소개 링크

### 카테고리 목록 `/categories/<category>`

브레드크럼, 주제 설명, 공개 글 수, 최신 글 행 목록, 전체 검색 진입점을 제공한다. 글이 없을 때에는 단순한 “준비 중” 문구 대신 다른 주제와 검증 원칙으로 이동시킨다.

### 검색 `/search`

정적 빌드에 포함된 공개 글 인덱스를 브라우저에서 검색한다. 제목·설명·주제명을 대상으로 하며 공개 글이 0건이면 그 사실과 공개 조건을 안내한다.

### 글 상세 `/posts/<slug>`

브레드크럼 → 주제·검증 배지 → 제목·작성/확인 날짜 → 요약 → 본문 → 테스트 정보 → 같은 주제의 다음 읽을거리 순서다. 데스크톱에서는 보조 정보를 오른쪽에 두고, 모바일에서는 본문 아래로 자연스럽게 쌓는다.

## 3. 컴포넌트 규칙

- 최근 글은 일반적인 2열 카드 목록으로 보여주고, 주제가 많아지면 목록 페이지로 확장한다.
- 카드에는 이미지·제목·요약·주제·날짜만 둔다. 대표 콘텐츠를 과하게 만들지 않는다.
- 배지는 주제와 직접 테스트 상태를 짧게 표시하는 데만 사용한다.
- 검색 입력과 버튼은 52px 이상으로 유지한다.
- 본문 링크는 밑줄과 청록색으로 식별한다.
- 표와 코드만 내부 가로 스크롤을 허용하고, 페이지 전체 가로 스크롤은 허용하지 않는다.
- 푸터는 간단한 브랜드 설명과 보조 링크로 끝낸다.

## 4. 반응형 규칙

- 0–479px: 검색 버튼은 입력 아래로, 글 목록 화살표는 생략, 상세 보조 정보는 본문 아래.
- 480–767px: 콘텐츠는 한 열, 헤더 내비게이션은 2행 허용.
- 768px 이상: 홈·주제 링크·대표 글·검증 기준을 2열 또는 3열로 확장.
- 1024px 이상: 글 상세는 본문 + 보조 정보 2열.
- 390px에서 제목, 설명, 메뉴, 입력, 표가 화면 밖으로 밀려나지 않아야 한다.

## 5. 구현 파일

- `src/layouts/BaseLayout.astro`: 전역 브랜드 헤더·주요 메뉴·검색 진입점·푸터
- `src/pages/index.astro`: 콘텐츠 중심 홈
- `src/pages/categories/index.astro`, `[category].astro`: 카테고리 아카이브
- `src/pages/search.astro`: 정적 공개 글 검색
- `src/pages/posts/[...slug].astro`: 읽기 화면·브레드크럼·관련 탐색
- `src/styles/tokens.css`: v1 색·폭·간격 토큰
- `src/styles/site.css`: v1 사이트 전용 레이아웃과 반응형 스타일

관리자 페이지·콘텐츠 계약·draft 공개 차단은 운영 안전장치이므로 이번 시각 재설계에서 변경하지 않는다.

## 6. QA 게이트

- 자동: `npm run check:content`, `npm run build`, `npm run check:build`
- 수동: 390px·768px·1440px에서 메뉴·검색·주제 목록·빈 상태·글 상세 확인
- 접근성: 키보드 포커스, 200% 확대, 표·코드의 제한적 스크롤, `aria-live` 검색 상태 확인
- 발행: 첫 글의 `status: draft` 유지. 디자인 QA 완료와 콘텐츠 발행 승인은 별도다.
