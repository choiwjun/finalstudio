## 2. 인프라 결정

### 2.1 1차 결정

**Cloudflare Pages + Astro + Git/Markdown**을 채택한다.

권장 구현 방향:

- 정적 생성기: Astro
- 공개 읽기 경로: DB를 호출하지 않는 정적 HTML
- 콘텐츠 원본: Git 저장소의 Markdown
- 배포: Cloudflare Pages
- 자동화: GitHub Actions와 Cloudflare Pages Deploy Hook
- 미디어: 직접 제작한 이미지와 검토된 객체 스토리지
- 출시 전 Cloudflare의 상업적 사용 조건과 최신 무료 요금제는 다시 확인한다.

### 2.2 Neon의 사용 시점

Neon은 처음부터 공개 페이지의 콘텐츠 저장소로 사용하지 않는다.

필요해질 때만 다음 상태를 저장하는 보조 저장소로 추가한다.

- 초안 상태
- 검토 상태
- 예약 발행 시각
- 검토 이력
- 자동화 실행 로그

Neon이 추가되어도 공개 페이지는 DB를 읽지 않는다.

### 2.3 Supabase + Vercel 전환 조건

다음 기능이 실제 로드맵에 확정될 때만 재검토한다.

- 다수 작성자의 계정과 권한
- 댓글·회원·멤버십
- RLS가 필요한 사용자별 데이터
- 동적 대시보드와 실시간 기능

Vercel Hobby의 상업적 사용 조건과 Supabase 무료 요금제의 일시정지·백업 조건은 출시 직전에 다시 확인한다. 광고 수익화 사이트에 무료 요금제를 그대로 적용한다고 가정하지 않는다.

### 2.4 필수 운영 조치

- OneDrive 바깥에 자동화용 Git clone을 둔다.
- private Git remote를 추가한다.
- `.planning/`과 내부 검토 자료가 배포 산출물에 들어가지 않도록 CI에서 차단한다.
- 정적 사이트의 이전 배포로 되돌리는 롤백을 먼저 테스트한다.
- `site/` 또는 정적 생성기의 입력·출력 경계를 정하고, CI에서 `.planning/` 파일이 산출물에 없는지 검사한다.

### 2.5 미디어·개인정보·동의 원칙

- 화면 캡처는 직접 만든 테스트 화면을 기본으로 하고, 계정명·메일·고객 데이터·토큰을 제거한다.
- 타사 로고·화면·템플릿을 재배포한다고 해석될 수 있는 사용은 출시 전 해당 약관과 권리를 확인한다. 불확실하면 텍스트 설명이나 직접 만든 예제로 대체한다.
- 템플릿·예제 파일은 우리 저작물과 제3자 자료를 구분하고, 재배포 권리가 없는 자료는 포함하지 않는다.
- 광고를 붙이는 지역의 개인정보·쿠키·동의 요구사항은 Privacy 페이지 하나로 끝난다고 가정하지 않고 출시 전 별도 점검한다.

## 3. 콘텐츠 자동화 파이프라인

자동화는 초안과 검증을 빠르게 만들지만, 승인 없이 콘텐츠를 공개하지 않는다.

```text
주제 후보
  → 주제 적합성 검토(Human)
  → 검색 의도·차별점 브리프
  → 공식·원문 자료 수집
  → 아웃라인 생성
  → 직접 실행·스크린샷·템플릿 확보(Human)
  → 초안 생성
  → 출처·주장 연결
  → 링크·중복·메타데이터·구조 검사
  → 다른 모델의 반증·오류 검토
  → 문체·경험 주장·숫자 검토(Human)
  → SEO·정책·개인정보 검토
  → PR 승인(Human hard gate)
  → 예약 시각에 정적 빌드·배포
  → sitemap/RSS 갱신
  → Search Console·성능·광고 상태 모니터링
  → 갱신·통합·중단·롤백
```

### 3.1 예약 발행 방식

Neon 없이 Git만으로 시작한다.

각 글의 최소 front matter는 `title`, `description`, `status`, `publishAt`, `topic`, `angle`, `author`, `sourceIds[]`, `testedAt`, `toolVersions`, `aiAssisted`로 한다. `slug`는 Markdown 파일 경로에서 생성한다. `author: TBD`와 `testedAt: TBD`는 `draft`에서만 허용하며, `scheduled`·`published`는 CI가 실제 값을 요구한다.

- 사람 승인으로 `main`에 병합된 글만 예약 발행 후보가 된다.
- front matter에 `status: scheduled`와 `publishAt`을 기록한다.
- 정적 빌드는 현재 시각보다 미래인 글을 산출물에서 제외한다.
- GitHub Actions가 하루 한 번 Deploy Hook을 호출해 예약 시각이 지난 승인 글만 공개한다.
- 배포 실패 시 수동 Deploy Hook 또는 일반 Git 배포를 사용할 수 있어야 한다.
- Neon은 예약 큐·검토 이력·실행 로그를 Git만으로 관리하기 어려워질 때 추가한다.

예약 발행은 미래 글을 자동으로 승인하는 기능이 아니다. 사람 승인을 거쳐 `main`에 병합된 글만 대상으로 한다. 현재 방식은 하루 한 번 실행하므로 예약 시각과 실제 공개 사이에 최대 약 24시간 차이가 날 수 있다. 분 단위 예약이 필요해질 때만 별도 scheduler를 검토한다. GitHub Actions 비밀값은 저장소 비밀에 두고 글이나 로그에 출력하지 않는다.

### 3.2 모델 분업

이번 기획과 초기 자동화의 역할 배정은 다음과 같다.

- Muse Spark 1.3 Contributor: `opencodex/command-code/meta/muse-spark-1.3-contributor` — 주제·독자·차별점·아웃라인
- Qwen 3.8 Flash: `opencodex/command-code/Qwen/Qwen3.8-Flash` — 초안과 구조화된 메타데이터
- DeepSeek V4 Flash: `opencodex/command-code/deepseek/deepseek-v4-flash` — 독립 반증·출처·논리 검토

초안 모델과 판정 모델은 같은 호출로 묶지 않는다. Command Code의 모델별 실제 비용·성공률은 아직 UNKNOWN이다. 주간 토큰 예산은 Human이 정하기 전까지 자동화 테스트를 글 1개로 제한하고 예약 실행을 켜지 않는다. 첫 테스트에서 실제 사용량·실패율을 기록한 뒤 예산을 승인한다. 개인정보·기밀정보·접근 토큰은 어떤 모델에도 보내지 않는다.

### 3.3 사람 승인 필수 지점

1. 주제를 발행 대상으로 채택할 때
2. 금융·건강·법률·보안 등 위험 주장이 포함될 때
3. “직접 테스트했다”와 같은 경험 주장을 할 때
4. 가격·날짜·수치·버전이 들어갈 때
5. 작성자와 전문성 소개를 확정할 때
6. 공개 브랜치에 병합하거나 기존 글을 삭제할 때

### 3.4 발행 규칙

- 검토 가능 시간이 확정되기 전 초반 총 발행 상한: 주 2개
- 검토 대기열이 밀리면 발행량을 줄이고 승인 기준은 낮추지 않는다.
- 자동 생성 글의 무인 자동 발행은 하지 않는다.
- 글마다 출처, 테스트 날짜, 차별점, 오류 해결 섹션을 기록한다.
- 모델이 작성한 글을 같은 모델이 최종 판정하지 않는다.
- Google Indexing API를 일반 블로그 발행 도구로 사용하지 않는다. sitemap과 정상 크롤링을 사용한다.

## 4. AdSense·검색 품질 게이트

Google은 자동화 자체보다 사용자 가치가 없는 대량·비독창 콘텐츠를 문제로 본다. 따라서 다음을 내부 발행 게이트로 둔다.

- 글 하나가 하나의 명확한 문제를 해결한다.
- 다른 글을 바꿔 쓴 수준이 아니다.
- 직접 검증한 결과나 원본 자료가 있다.
- 출처가 필요한 주장은 출처와 확인 날짜가 있다.
- 제목·설명·구조화 데이터·이미지 대체 문구도 실제 내용과 일치한다.
- About, Author, Contact, Privacy, Editorial Policy 페이지가 있다.
- 광고와 본문을 구분할 수 있다.
- 자체 광고 클릭, 클릭 유도, 트래픽 조작을 하지 않는다.
- `.planning/`과 내부 문서가 공개되지 않는다.

AdSense 승인 기준·승인 기간·필요 글 수에 대한 공식 숫자는 확인되지 않았으므로 보장하지 않는다. 내부 준비 기준으로 **완전히 검토된 글 20개 이상**을 하나의 참고선으로 사용하되, 이는 Google의 공식 요구사항이 아니다.

### 4.1 내부 pass/fail 체크리스트

발행은 아래 항목을 모두 통과할 때만 가능하다.

- [ ] 하나의 글이 하나의 구체적인 문제를 해결한다.
- [ ] `angle`에 기존 글과 다른 독자 가치가 한 문장으로 적혀 있다.
- [ ] 실제 테스트 기록·스크린샷·템플릿 중 하나가 첨부되어 있다.
- [ ] 테스트 날짜와 도구 버전이 front matter에 있다.
- [ ] 중요한 주장마다 `source_ids[]`와 확인 날짜가 있거나, 주장을 삭제했다.
- [ ] 가격·수치·날짜·버전·경험 주장을 사람이 확인했다.
- [ ] 오류 해결 또는 제한사항 섹션이 있고 해당 없음이면 그 이유를 적었다.
- [ ] 제목·설명·canonical·구조화 데이터·alt가 본문과 일치한다.
- [ ] 저작권·개인정보·YMYL·광고 배치 검토를 통과했다.
- [ ] 작성자가 PR을 검토하고 `main`에 병합했다.

초기에는 비교할 글 수가 적으므로 중복·유사도 검사는 자동 차단보다 사람이 수행한다. 글이 10개 이상 쌓이면 exact title/slug와 유사 문장 검사를 CI에 추가하고 기준값을 별도 기록한다.

### 1주차 — 방향과 기반

- 핵심·인접 주제의 세부 범위를 확정한다.
- OneDrive 밖 작업 clone과 private Git remote는 Human이 제공할 때 구성한다. 그 전에는 현재 로컬 저장소만 사용한다.
- Astro 사이트 구조와 글 front matter를 만든다.
- `.planning/`이 빌드 산출물에 들어가지 않는 CI 검사를 만든다.
- About·Author·Contact·Privacy·Editorial Policy는 공개 전 검토용 초안으로 만든다.

### 2주차 — 수동 품질 기준

- 핵심 주제 글 2개를 gold-standard로 제작하고, 검토 가능 시간에 따라 1개를 추가한다.
- 스크린샷·템플릿·오류 해결 섹션을 포함한다.
- 글 품질 체크리스트를 실제 글에 적용한다.
- 중복·출처·메타데이터 검사의 최소 버전을 정의한다.
- 사이트의 정적 빌드와 기본 SEO 구조를 구현한다.

### 3주차 — 자동화 초안

- 주제 큐와 글 브리프를 생성한다.
- 출처 수집과 draft 브랜치 생성을 자동화한다.
- Qwen 3.8 Flash를 초안 담당으로, DeepSeek V4 Flash를 독립 반증 담당으로 사용한다.
- Muse Spark 1.3 Contributor는 주제·차별점·아웃라인 검토에 사용한다.
- PR 승인 전 자동 검사를 실행한다.
- 예약 발행은 승인된 글만 대상으로 구현한다.
- 자동화 실패 시 수동 발행 경로를 유지한다.

### 4주차 — 제한적 운영

- 총 4~6개의 검토 완료 글을 목표로 하되 품질 기준을 우선한다.
- sitemap·RSS·Search Console 연결은 도메인과 계정이 승인된 경우에만 진행한다.
- Lighthouse·모바일 성능·canonical·robots를 검사한다.
- 배포 롤백을 실험한다.
- 글당 검토 시간과 자동화 실패 로그를 측정한다.
- 내부 기준인 검토 완료 글 20개에 도달하는 시점을 60~90일 사이에서 다시 결정한다.
- AdSense 신청은 준비 게이트 통과 뒤 Human이 별도로 결정한다.

## 6. 성공 측정

처음 30일에는 광고 수익을 핵심 성공 지표로 사용하지 않는다.

### 선행 지표

- 발행된 글 중 품질 게이트 통과 비율
- 색인된 페이지 수
- Search Console 노출·클릭
- 글당 사람 검토 시간
- 출처 누락·중복·사실 오류 수
- 자동화 실패와 롤백 횟수

### 중단 신호

- 검토 대기열이 계속 증가한다.
- 직접 검증 없이 발행되는 글이 생긴다.
- 주제 간 중복이 늘어난다.
- 색인·노출보다 글 생성 수만 증가한다.
- 정책·개인정보·저작권 검토가 누락된다.

## 7. Human 승인과 남은 결정

기획 방향은 다음 기본값으로 진행한다. Human이 바꾸면 이 문서와 실행 순서를 함께 갱신한다.

- 시장: 한국어·한국 시장
- 작성자: Human이 지정하기 전까지 공개 글을 만들지 않음
- 초기 발행: 주 2개 이하
- 기술: Astro + Cloudflare Pages + Git/Markdown + GitHub Actions
- DB: 초기에는 없음. Neon은 workflow 상태가 Git만으로 부족해질 때 추가
- 모델: 세 모델 모두 Command Code 경유; Muse=전략, Qwen=초안, DeepSeek=독립 반증
- 예약: 하루 한 번 빌드로 최대 약 24시간 지연을 허용

Human이 반드시 결정할 항목:

1. 최종 작성자 정체성
2. 주당 실제 검토 가능 시간과 백업 검토자
3. 도메인과 Google 계정
4. AI workflow 글에 공개할 도구·입력·결과의 범위
5. 실제 스크린샷·로고·템플릿 사용 정책
6. 초기 Git/PR 운영으로 시작하는 것에 대한 승인

검토 시간이 확정되기 전까지 주 2개를 초과하는 예약 발행은 허용하지 않는다.
